## 1. 架构原则

1. **模块化单体优先**：个人单用户系统，先做一个可维护的单体进程（FastAPI + 调度器），明确模块边界，避免过早微服务化。
2. **适配器隔离数据源**：所有外部数据经 `Provider` 接口进入，统一限流、重试、缓存、时效标注；换源不改分析代码。
3. **原始数据不可变**：抓到的原文、行情快照、API 响应一律追加写入，带哈希与元数据；分析层只读，可随时重放。
4. **证据驱动**：知识层（claims/events/theses）是全系统的枢纽，分析结论必须挂 claim_id 才能发布。
5. **计算与生成分离**：确定性计算（指标、回归、回测）用代码完成；LLM 只负责抽取、解释、写作、反驳，不负责算术与事实发明。
6. **可复现**：每次分析记录「数据快照 + 代码版本 + 参数 + Prompt 版本 + 模型名」，结果可重跑。
7. **优雅降级**：数据源/LLM 故障时，看板显示陈旧标记，简报降级为模板 + 已有证据，不静默输出错误结论。
8. **本地优先、零云依赖**：默认全部跑在本机；需要外盘实时/被墙数据时才引入代理或 VPS（可插拔）。

### 2.1 分层职责

| 层 | 职责 | 不做什么 |
|---|---|---|
| 采集适配层 | 拉取、限流、重试、缓存、时效标注、源健康 | 不做业务判断，不改数据含义 |
| 标准化层 | 字段映射、单位换算、时区、合约/品种映射、复权 | 不做聚合与预测 |
| 存储层 | 原始快照（不可变）+ 规范表 + 分析结果 + 向量/全文索引 | 不做计算 |
| 知识层 | 实体/事件/断言/论点/证据/可信度/冲突/溯源 | 不生成交易计划 |
| 分析层 | 指标、周期状态、定价归因、相关性、传导、类比、持仓 | 不直接对用户说话 |
| 决策层 | 信号、情景、计划、风控、回测、预测登记与对账 | 不下单、不碰账户 |
| 生成层（LLM） | 抽取、摘要、解释、写作、反驳、核查 | 不算数、不无证据断言 |
| 应用层 | API、页面、导出、告警、任务管理 | 不做分析逻辑 |

## 3. 运行时视图

单机常驻进程（二选一，推荐 A）：

**A. 单体进程（推荐 V1）**
- `uvicorn` 启动 FastAPI，内嵌后台线程/AsyncIO 调度器（APScheduler）执行采集与分析任务。
- 前端构建为静态文件，由 FastAPI 直接托管（`/`），API 在 `/api/*`。
- SQLite（WAL）作为唯一 OLTP 库；DuckDB 以只读方式查询 Parquet 做分析；FTS5 做全文检索。
- 优点：部署简单、调试方便、备份容易；缺点：重任务会与 API 抢资源 → 用任务队列（SQLite 表 + 单 worker）串行执行重任务。

**B. 双进程（V1.5 可选）**
- `api` 进程只服务请求；`worker` 进程（同一代码，`--worker` 模式）跑采集/分析/报告。
- 通过 SQLite 任务表通信；适合后续接 Docker 或云部署。

**C. 容器化（V2 可选）**
- `docker-compose.yml`：app +（可选）postgres +（可选）proxy 侧车；数据卷持久化。

## 5. 数据架构

### 5.1 存储分层

| 层 | 介质 | 内容 | 保留策略 |
|---|---|---|---|
| Raw（原始层） | 文件系统 `data/raw/<source>/<date>/...` + 指针入库 | 原始响应、PDF、网页快照、行情快照、LLM 原始输出 | 永久（可压缩）；新闻正文仅官方/公开源 |
| Normalized（规范层） | SQLite 表 | 合约、行情、宏观序列、文档元数据、实体、事件、断言、持仓 | 永久 |
| Analytics（分析层） | DuckDB + Parquet 分区（`dataset/date/`） | 指标、因子、相关性、回测结果、类比 | 5 年滚动（可配） |
| Knowledge（知识层） | SQLite + FTS5（+ 可选 LanceDB） | claims、events、theses、证据链、向量 | 永久 |
| Derived（展示层） | SQLite 缓存表 / 前端缓存 | 看板聚合、日报 HTML | 90 天 |

### 5.4 数据契约（Data Contract）

每个数据集必须有机器可读契约（Pydantic 模型 + 版本号）：

- 必填元数据：`source`、`fetched_at`、`published_at`、`delay_sec`、`unit`、`currency`、`timezone`。
- 行情：OHLC 一致性校验、非负成交量、涨跌停标记、换月标记。
- 宏观：频率与修订标记（revision）、季节调整标记（SA/NSA）。
- 文档：URL 规范化、去重键（`canonical_url + sha256`）、正文抽取状态。
- 契约破坏 → 任务失败告警，不静默写库。

## 6. 采集与适配器设计

### 6.1 Provider 接口

```python
class Provider(Protocol):
    name: str
    domain: str          # market/macro/news/positions/calendar/filings
    latency: str         # realtime/delayed/daily
    def fetch(self, task: FetchTask) -> FetchResult: ...
    def health(self) -> HealthStatus: ...
```

- `FetchTask`：数据集、标的、时间范围、优先级。
- `FetchResult`：记录列表 + 元数据（来源、抓取时间、延迟、哈希、原始响应路径）。
- 注册表按 `(domain, dataset)` 维护**优先级链**（主源 → 备源 → 缓存），失败自动降级并记录。

### 6.2 统一客户端约束

- `httpx` 异步客户端：UA、Referer、超时、限速（1–2 req/s/域）、并发 ≤3、指数退避、磁盘缓存（ETag/Last-Modified）。
- 代理支持：按源配置 `proxy`（默认直连；Yahoo/CFTC/LME 等需代理的源标记 `requires_proxy`，未配置时跳过并不告警）。
- 合规开关：每源 `license` 字段；`store_body` 白名单（官方/公开）；新闻正文默认只存标题、摘要、URL 与快照哈希。

### 6.3 时效与延迟标注

- 所有行情带 `delay_sec`：国内期货 ~3–60s；免费外盘 15min 或日线；美债/宏观为收盘/发布值。
- UI 用徽标显示「实时 / 延迟 15 分钟 / 日线 / 收盘」，分析文本引用价格时自动带上时点与来源。
- 交易时段感知：国内日盘/夜盘、美国 DST、日本/欧洲时段；非交易时段不产生"价格异动"告警。

### 6.4 主力合约与换月

- 只存「品种 + 合约 + 日期」原始行情；另建 `continuous_series`（按持仓量最大选择主力，记录换月日与价差），同时保留未复权与复权两种序列。
- 分析默认用复权连续序列；涉及具体交易价位时切回具体合约。

### 6.5 多源核对

- 每日收盘后，用交易所官方结算价核对主源；偏差 > 0.2% 告警并标记该源当日降权。
- 宏观数据以官方（BLS/BEA/央行）为准，第三方仅作补充。

## 7. 知识层：抽取、可信度与溯源

### 7.1 处理流水线

```
document → 正文抽取 → 分块 → LLM 抽取(claims/entities/events) → 实体消歧
        → 去重/聚类（同事件多源）→ 可信度评分 → 冲突检测 → 入知识库 → 索引(FTS/向量)
```

### 7.2 抽取输出（强 Schema）

```json
{
  "claims": [
    {"type": "fact", "subject": "美联储", "predicate": "维持利率不变",
     "object": "4.25%-4.50%", "valid_at": "2026-09-17", "quote": "...",
     "span": [120, 260], "confidence_hint": 0.9}
  ],
  "entities": [{"type": "institution", "name": "Federal Reserve"}],
  "event": {"type": "monetary_policy", "subtype": "fomc_decision", "date": "2026-09-17",
            "instruments": ["XAUUSD", "DXY", "US10Y"]},
  "sentiment": {"label": "hawkish", "score": -0.3}
}
```

- 引用 `quote` 必须在原文中精确存在（程序校验，不允许改写）；不通过则重试/丢弃并告警。
- 数字抽取后与结构化数据源对账（如利率、价格、库存），不一致进入人工复核队列。

### 7.3 实体消歧与事件聚类

- 实体：别名表 + 规则 + 嵌入相似度 + 人工确认；关键实体（人/机构/品种）维护固定 ID。
- 事件聚类：时间窗（±24h）+ 实体重叠 + 文本相似度；同事件保留各源表述与差异。

### 7.4 可信度引擎

```
confidence = sigmoid(β·features)
features = [来源等级, 独立印证数, 具体性, 时效, 利益冲突, 来源历史错误率, 抽取置信度]
```

- 来源历史错误率：每条被证伪的断言按来源回填；用 Brier 分数转权重。
- 冲突：同一 `(subject, predicate)` 不同 `object` 并存 → 生成 `conflict` 记录，简报中显式并列。
- 所有分数保留明细，可人工覆写（覆写进审计日志）。

### 7.5 溯源与取证实现

1. **内容寻址**：原文按 `sha256` 存储；任何检索结果可校验。
2. **快照**：官方网页保存 HTML/MHTML（不含付费墙内容）；行情保存原始 JSON；LLM 保存完整请求/响应（脱敏）。
3. **引用定位**：`document_spans` 存字符区间与引文，前端高亮。
4. **证据包导出**：结论 → 证据链 → 原文快照 + 哈希清单 + 时间戳 + 生成参数，打包 zip/PDF。
5. **审计**：结论/论点/计划的每次修改记录 actor、时间、前后哈希。

## 8. LLM 编排

### 8.1 角色分工（分模型、分温度）

| 角色 | 任务 | 模型档位 | 温度 | 输出 |
|---|---|---|---|---|
| Extractor | 实体/断言/事件抽取、摘要 | 小/快（deepseek-chat 低价档） | 0.1 | JSON（Schema 校验） |
| Analyst | 定价叙事、周期解读、情景推演 | 强推理（reasoner） | 0.3 | 结构化分析 + 引用 |
| Skeptic | 反驳、找反例、检查主次动力 | 强推理（可与 Analyst 不同模型） | 0.2 | 反论点清单 |
| Fact-Checker | 数字/引文/时点核对 | 规则 + 小模型 | 0 | 通过/不通过/存疑 |
| Editor | 简报排版、风格统一 | 中档 | 0.4 | Markdown |
| Persona | 达利欧/索罗斯/德鲁肯米勒视角解读（可选） | 强推理 | 0.5 | 观点卡（明确标注"框架模拟"） |

### 8.2 关键机制

- **检索增强**：先检索 claim/文档/历史类比，再生成；Prompt 中强制「只能用给定证据」。
- **引用强制**：输出 JSON 中 `citations: [claim_id]`；无引用的句子由后处理标记为"推断"或删除。
- **两轮核查**：Draft → Verifier（逐句检查引用存在性与数字一致）→ Revise。
- **缓存**：按 `task + input_hash + prompt_version + model` 缓存；相同输入不重复计费。
- **预算**：每日 token 上限、单任务上限、超限降级（跳过 Persona/解释，只保留简报）。
- **可复现**：记录模型版本、prompt 版本、参数、输入快照哈希；支持离线回放。
- **成本估算**：500 条新闻抽取 + 4 份简报 + 若干分析 ≈ ¥3–15/天（DeepSeek 价格量级），可设月度上限。

### 8.3 Prompt 资产

- 存放 `prompts/` 目录，版本化（`extract_claim.v3.md`），代码引用版本号；变更需通过评估集（50 条人工标注样本）。

## 9. 分析计算层

| 计算 | 方法 | 频率 | 产出 |
|---|---|---|---|
| 指标 | 均线、ATR、动量、分位、持仓变化 | 每日/盘中 | `indicators` |
| 周期状态 | 六维打分 + 规则状态机（V1）；HMM（V2） | 每日 | `regime_states` |
| 定价归因 | 因子回归/弹性 + 情景分解 | 每日 | `factor_contribs` |
| 相关性/传导 | 滚动相关、DCC-GARCH、Granger、转移熵 | 每日/每周 | `correlations`、`graph_edges` |
| 情绪/风向 | 文本情感 + 持仓分位 + 期权 + 基差合成 | 每日 | `sentiment`、`wind` |
| 拥挤度 | 多指标合成 + 分位 | 每日 | `crowding` |
| 历史类比 | 状态向量 + 相似度 + 结果统计 | 每周 | `analogs` |
| 参与者 | 持仓画像、对手盘推断、影响力 | 每周 | `players_view` |
| 回测 | walk-forward，含成本 | 按需/每周 | `backtests` |

- **计算隔离**：分析层只读规范表与原始快照；结果写分析表，带 `code_version` 与 `dataset_snapshot_id`。
- **数值卫生**：单位、时区、复权、样本量、置信区间必须随结果输出；小样本（n<10）不展示统计结论。
- **禁止 LLM 算数**：所有数值来自代码；LLM 只引用结果表。

## 10. 决策层

```
信号 → 候选论点 → 情景树 → 交易计划 → 风控校验 → 人工确认 → 执行记录 → 对账/复盘
```

- **论点（Thesis）**：方向、时间窗、先验/后验概率、证据列表、失效条件、主要动力。
- **情景（Scenario）**：基线/乐观/悲观，概率和 100%，触发条件可观测。
- **计划（TradePlan）**：合约、方向、入场区、止损、目标、仓位、时间止损、失效条件、国内映射、证据。
- **风控（RiskEngine）**：单笔风险、总仓位、单品种上限、相关性合并、日亏损/连亏熔断、涨跌停/保证金/流动性检查。
- **回测（Backtest）**：信号历史表现，含成本与滑点；walk-forward 防过拟合。
- **预测账本（Prediction Ledger）**：所有可证伪判断自动登记概率与时点；到期对账；Brier/命中率/校准曲线。
- **执行记录**：人工录入实际成交（或截图解析，V2），计算滑点与纪律分。

## 12. 调度与实时

| 任务 | 频率 | 说明 |
|---|---|---|
| 行情快照（国内期货/股票） | 交易时段 15–60s | 新浪/东财；限速与缓存 |
| 行情快照（外盘） | 交易时段 60–300s | 免费源 15min 延迟，标注 |
| 新闻 RSS 轮询 | 2–5 min | 官方源优先；去重 |
| 快讯/日历轮询 | 5–10 min | 经济日历、重要数据 |
| 盘中异动扫描 | 1 min | 价格/量/持仓/基差 |
| 盘前简报 | 07:30 | 生成 + 推送 |
| 盘后简报 | 21:00 | 生成 + 推送 |
| 收盘数据入库/核对 | 15:30 / 次日 03:00 | 官方结算价、持仓排名、库存 |
| COT/ETF/13F | 周五/每日/季度 | 按发布节奏 |
| 每周深度（周期/类比/复盘） | 周日 10:00 | 重计算 |
| 月度模型评估 | 每月 1 日 | Brier、信号衰减 |

- 任务表驱动：`jobs`（定义）+ `job_runs`（执行）；支持手动触发、重跑、跳过、超时。
- 单 worker 串行重任务；轻任务并发；失败重试（指数退避，最多 3 次）并告警。
- 交易日历：中国节假日/调休、美国节假日/DST、日本/欧洲；夜盘归属下一交易日。
- 告警通道：站内（数据库 + SSE）默认；邮件/企业微信/Server 酱可插拔；静默时段可配。

## 16. 关键技术风险与备选

| 风险 | 影响 | 备选/缓解 |
|---|---|---|
| Python 3.8 过旧 | akshare/新库不可用 | 安装 3.12；或先锁旧版本（不推荐） |
| 国内直连外盘受限（Yahoo/CFTC/LME） | 外盘数据延迟/缺失 | 免费替代（FRED/新浪 hf_/CME 延迟）；可选代理/VPS |
| 交易所接口改版 | 日行情/持仓中断 | 多源 + 官方结算价核对 + 告警；akshare 更新 |
| LLM 幻觉 | 错误结论 | 引用强制 + 数字核对 + 双模型 + 人工闸门 |
| 数据版权 | 法律风险 | 白名单 + 仅元数据 + 不对外分发 |
| 单机故障/断电 | 数据丢失 | 每日备份 + 云端可选备份 |
| 过度拟合回测 | 实盘亏损 | walk-forward + 样本外 + 成本假设 |
| 用户执行纪律 | 计划不执行 | 纪律分、违规标记、连亏熔断 |
