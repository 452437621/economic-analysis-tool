# 17 · 黄金监控与综合研判（V1.3）

> 目标：把「央行购金 / 全球黄金 ETF / 黄金租赁·掉期·存储 / 纽约·伦敦·上海库存 / 做市商黄金合约」纳入可监控指标，并结合实际利率、美元、上海溢价等驱动，形成可解释的黄金综合评分，支撑"谁在抛售黄金"这类市场叙事的基本面判断。
>
> 参考：宋鸿兵观天下《谁在抛售黄金》（B 站 opus 1270088302679031808）提出从央行购金、ETF 持仓、BIS 黄金租赁/掉期/存储、三地库存与做市商合约等维度判断金价。本文档记录本系统的指标落地方式、数据源、评分算法与局限。

### 2.3 中国央行购金的价格重估剔除

`CN_GOLD_RESERVES_USD` 是美元计价的储备规模，会随金价波动。评分时：

```
购金代理% = 储备变动% − 伦敦金现同期涨跌幅%
```

这样 2026-09→10 储备美元值 −5.29%、同期金价 −9.74%，得到购金代理 **+4.45%**，即储备量仍在小幅增加，而非表面上的“下降”。

## 3. 综合评分算法

对每个指标：

1. 取最近 400 期观测（`gold_metrics`），按 transform 归一化到 `-1..1`：
   - `pct_change_1m` / `pct_change_3m`：近 30/90 天变化 ÷ scale；
   - `level`：水平 ÷ scale；
   - `percentile`：历史分位（最近 104 期）；
   - `level_and_change`：实际利率水平与变化加权。
2. 乘以方向：`+1`（央行/ETF/溢价/租赁紧张 → 金价利多）、`-1`（实际利率/美元/库存/投机持仓 → 利空）。
3. 贡献 = 权重 × 方向化得分。
4. 综合分 = Σ贡献 ÷ Σ**已获取**权重 × 100；`coverage` = 已获取权重 ÷ 全部权重。

| 综合分 | 标签 |
|---|---|
| ≥ 50 | 强多 |
| 18 ~ 50 | 偏多 |
| −18 ~ 18 | 中性 |
| −50 ~ −18 | 偏空 |
| ≤ −50 | 强空 |

局限：

- 权重为经验权重（宏观驱动 24、央行 24、ETF 20、库存/溢价 13、租赁/掉期 23、做市商 18、动量 10，合计 145），未做回测优化；
- 不可得指标不参与评分，按已获取权重重新归一，`coverage` 偏低时结论置信度更低；
- CFTC 分类持仓是代理指标，不代表 JPM/汇丰实际账簿；
- BIS 数据靠手动录入，注意录入日期与口径。

## 4. 采集与调度

```
# 手动采集（约 60-90s，下载 WGC/CFTC/LBMA）
python -m app.jobs.runner --job collect_gold

# 异步触发
curl -X POST http://127.0.0.1:8765/api/gold/refresh
```

- 任务注册：`JOBS["collect_gold"]`（`app/jobs/runner.py`）、`JOBS_DEFAULT`（`app/init_db.py`，16:40）、调度器启动回补 + 每日 16:40（`app/platform/scheduler.py`）。
- 表结构：`gold_metrics`（code + as_of 唯一）、`gold_provider_runs`（数据源健康）。
- 存储幂等：按 `(code, as_of)` upsert，重复运行只更新。

## 5. API 契约

| 端点 | 说明 |
|---|---|
| `GET /api/gold/overview?series_limit=160` | 评分 + 因子 + 序列 + 数据源 + 手动指标 + 方法说明 |
| `GET /api/gold/series?code=&limit=` | 单指标历史序列（未知 code → 404） |
| `GET /api/gold/providers` | 各 provider 最近运行状态 |
| `POST /api/gold/refresh` | 异步触发一次采集（约 60s 后生效） |
| `POST /api/gold/metrics` | 手动录入（仅 manual 指标）：`{code, value, as_of?, source?, note?}`；自动指标返回 400 |
