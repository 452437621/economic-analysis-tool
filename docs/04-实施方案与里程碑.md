## 1. 实施策略

### 1.1 三条原则

1. **垂直切片优先**：每个里程碑都交付"可用的端到端能力"，而不是先铺完所有底层。第一刀切在「数据 → 证据 → 简报」这条主链上，因为它是所有后续分析的地基，也能最快产生日常价值。
2. **证据链先行**：先做溯源与可信度（FR-4），再做花哨的分析。理由：LLM 分析没有证据约束必然幻觉，后期返工成本极高。
3. **可验证再扩展**：每个阶段结束都跑验收清单；数据源不可用、指标不对、回测过拟合，都必须在进入下一阶段前解决。

### 1.2 交付节奏

- 阶段制：M0 → M5，每个阶段结束产出可运行版本 + 变更说明。
- 每阶段首日对齐范围，末日演示 + 验收；用户可随时提调整，但范围变更进入下一阶段（避免无限蔓延）。
- 试运行（M6）两周：真实使用、记录问题、校准模型，再决定是否进入 V1.1。

## 4. 里程碑详情

### M0 环境与骨架（2–3 人日）

**目标**：一条命令启动空系统，数据库就绪，配置可管理。

- 初始化 Git 仓库、目录结构、`.gitignore`、`.env.example`。
- Python 3.12 venv、`pyproject.toml`（FastAPI、SQLAlchemy、httpx、pydantic-settings、apscheduler、pandas、duckdb）。
- SQLite 初始化 + Alembic 迁移框架 + 核心表第一版。
- 配置系统（`config/default.yaml` + 环境变量覆盖 + 密钥加载）。
- 日志、健康检查 `/api/system/health`、任务表与调度器骨架。
- 前端脚手架（Vite + React + TS + Tailwind），空看板。
- `scripts/setup.ps1`、`scripts/start.ps1`、`scripts/backup.ps1`。
- 单元测试框架 + CI 脚本（本地 pre-commit）。

**验收**：`setup.ps1` 一次成功；`start.ps1` 后打开 `127.0.0.1:8765` 看到空看板与健康状态；`pytest` 全绿。

### M1 数据地基（5–7 人日）

**目标**：核心行情与宏观数据每日自动入库，看板可看多资产走势。

- Provider 框架：注册表、限流、重试、缓存、源健康、时效标注。
- 国内期货：日线全品种回补 + 主力换月 + 实时快照（新浪）；持仓排名、库存、基差（至少铜/金/油/豆粕）。
- A 股：指数 + 有色个股行情与基础财务（东财/akshare）。
- 外盘：FRED（美债/TIPS/美元/油价）+ 新浪外盘 15 分钟快照（金/银/油/铜）+ stooq 兜底。
- 汇率：USDCNH/USDJPY/EURUSD + DXY 代理口径。
- 新闻：官方 RSS（Fed/Treasury/白宫/ECB/BOJ/统计局/发改委）+ 新浪滚动标题。
- 经济日历：akshare 日历 + 官方数据源。
- 标准化：单位、时区、合约映射、复权、换月；数据契约校验。
- 基础看板：多资产价格、涨跌、时点/延迟徽标、数据源健康页。
- 数据质量报告（缺失、延迟、对账偏差）。

**验收**：连续 3 个交易日自动采集无致命错误；看板 20+ 资产正确显示；与交易所官方结算价偏差 < 0.2%；数据源故障演练通过。

### M2 证据与简报（7–10 人日）

**目标**：每日盘前/盘后简报自动生成，每条结论可溯源。

- 文档存储：原文快照、哈希、URL 规范化、去重、正文抽取（官方页/RSS）。
- 抽取流水线：实体/断言/事件 Schema + 程序校验（quote 必须原文存在）。
- 实体消歧、事件聚类、冲突检测。
- 可信度引擎 v1（来源等级 + 印证 + 具体性 + 时效）。
- 证据链 UI：结论 → 断言 → 原文高亮；证据包导出。
- LLM 编排：抽取/分析/核查/编辑四角色 + 缓存 + 预算 + 调用审计。
- 简报生成器：盘前/盘后模板（按 01 文档 10.1），生成 → 编辑 → 版本 → 导出 Markdown/PDF。
- 研究问答 v1（带引用，SSE 流式）。

**验收**：连续 5 天简报可用；抽查 20 条结论 100% 可展开到原文；数字一致率 ≥ 98%；单份简报生成 ≤ 10 分钟；无引用断言自动标记。

### M3 分析引擎（10–14 人日）

**目标**：看板回答"现在在周期哪里、价格在交易什么、跨市场怎么传导、历史上像哪段"。

- 指标库：均线/ATR/动量/分位/持仓/基差/月差/金银比/铜金比。
- 周期引擎：美/中/日/欧六维打分 → 四象限 + 过渡态 + 债务可持续性。
- 定价归因：黄金/原油/铜/铝/美债/汇率/股指的因子模型与贡献度；情景分解。
- 相关性/传导：滚动相关矩阵、DCC-GARCH（可选）、Granger、转移熵、事件研究；因果图（Cytoscape 可视化）。
- 情绪/风向：新闻情感、COT 分位、ETF 流量、期权 skew（若可得）、拥挤度合成。
- 历史类比：事件库 ≥30 个；状态向量检索 Top-5；结果分布；差异分析。
- 参与者视图：九类画像 + 持仓/流量/对手盘推断。
- 看板页面：资产详情、周期、相关矩阵、类比、参与者。

**验收**：周期定位有证据与置信度；黄金/原油/铜定价归因可解释近 3 个月主要波动；传导图至少 10 条确认边有数据支撑；类比结果标注样本量与风险。

### M4 决策系统（8–12 人日）

**目标**：从论点到交易计划到复盘闭环，且风控可拦截。

- 论点/情景管理：先验/后验概率、证据、失效条件、贝叶斯更新日志。
- 信号引擎：五类信号 + 回测（walk-forward，含成本）。
- 交易计划生成与模板；风控引擎（单笔/总仓/相关性/熔断/涨跌停/保证金）。
- 国内映射：外盘信号 → 国内合约/股票；汇率、价差、夜盘、交割月规则。
- 预测账本与对账：Brier、命中率、校准曲线。
- 交易日志与纪律分（违规交易标记）。
- 计划卡 UI、执行记录、对账页面。

**验收**：至少 3 个品种生成完整计划并通过风控；回测报告可复现；预测账本自动出周报；模拟执行 2 周无规则性错误。

### M5 打磨与验收（5–7 人日）

- 告警中心（站内 + 邮件/企业微信/Server 酱可选）、静默时段。
- 导出：简报 PDF、证据包 zip、Excel 数据。
- 系统页：任务、成本、日志、备份/恢复、数据源开关。
- 性能优化（首屏、查询索引、任务并发）。
- 安全与合规检查（密钥、依赖、监听地址、免责声明）。
- 文档：安装/使用/扩展/排障；演示数据与示例。
- 全量回归测试与验收清单。

**验收**：01 文档第 14 节 8 条 DoD 全部通过。

### M6 试运行与校准（2 周）

- 每日真实使用：盘前简报、盘中告警、盘后复盘。
- 问题清单与优先级修复（只修 P0/P1）。
- 模型校准：来源可信度、周期权重、信号参数。
- 决策复核：记录"系统建议 vs 人工判断 vs 实际结果"。
- 输出 V1.1 建议（是否加自动交易接口、付费数据、云端部署）。

## 6. 关键路径与并行策略

```
M0 ──► M1（数据）──► M2（知识/简报）──► M3（分析）──► M4（决策）──► M5（验收）──► M6
                 └──────────────► 前端看板可并行迭代
```

- **关键路径**：T1.1 → T1.2 → T2.2 → T3.2/T3.3 → T4.2/T4.3 → M5。
- **可并行**：
  - M3 期间，M4 的信号规则与回测框架可提前开发（依赖指标库）。
  - 前端页面可与后端并行（先用 mock 数据）。
  - 历史事件库录入（T3.6）是内容工作，可与代码并行。
- **风险缓冲**：数据源调试（外盘被墙、交易所改版）预留 2–3 天；LLM Prompt 调优预留 2 天。

## 7. 测试策略

| 层级 | 内容 | 工具 | 通过标准 |
|---|---|---|---|
| 单元测试 | 指标计算、仓位、风控、时区/单位换算、可信度公式 | pytest | 核心模块覆盖率 ≥ 80% |
| 契约测试 | 每个 Provider 用录制样本回放，字段/类型/单位校验 | pytest + VCR | 契约破坏即失败 |
| 集成测试 | 采集 → 标准化 → 分析 → 简报全链路（临时 SQLite） | pytest | 每日回归通过 |
| 数据质量 | 缺失、延迟、异常值、对账偏差 | 自定义检查 | 偏差 > 0.2% 告警 |
| 回测验证 | walk-forward、样本外、成本敏感性 | 自建框架 | 无未来函数；成本假设明确 |
| LLM 评估 | 50 条人工标注样本：抽取准确率、引用正确率、数字一致率、幻觉率 | 评估脚本 | 引用正确率 ≥ 98%，数字一致 ≥ 98% |
| 端到端 | 启动 → 简报 → 计划 → 对账 | Playwright（可选） | 主流程无阻塞 |
| 恢复演练 | 备份 → 误删 → 恢复 | 脚本 | 30 分钟内恢复 |
