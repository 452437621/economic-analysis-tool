# 32 · 专题研判与多标的融合（V3.0）

> 菜单「专题研判」用一套配置 + 适配器框架承载多个研究专题。首版包含 **黄金研判**（并入 `golden_analysis` 的正交信号）与 **洛阳钼业研判**（东财自采集 + 独立项目分析逻辑移植）。页面为「主题 tab + 页内锚点分区长页」，不是简单的两页叠加。

## 1. 架构

```text
config/topics.yaml                 # 专题注册表：顺序/显隐/标题/分区/信号权重
config/topics/luoyang.yaml         # 洛阳参数：标的、基准、情景假设、持仓默认值、评分权重
backend/app/topics/config.py       # YAML 加载 / 校验 / mtime 缓存
backend/app/topics/scoring.py      # 统一 -1..1 因子、combine_factors、标签
backend/app/topics/storage.py      # 通用长表存储、数据源运行、持仓设置
backend/app/topics/gold.py         # 黄金 adapter（复用 app/gold/*）
backend/app/topics/luoyang/        # 洛阳 adapter：data / analysis / payload
backend/app/api/topics.py          # /api/topics/*
frontend/src/views/TopicsView.vue # tab + 锚点导航 + kind 渲染器
```

新增专题 = 在 `config/topics.yaml` 增加 topic 块 + 在 `backend/app/topics/__init__.py::ADAPTERS` 登记 `module:function`。只改布局/顺序/显隐时只改配置；新算法才需要写 adapter。

配置按文件 mtime + 大小缓存（`topics.yaml` 与 `config/topics/*.yaml` 都在缓存键内），修改后下一次请求生效；非法 YAML/kind/重复 id 抛 `TopicConfigError`，接口返回 500 而不是白屏。

## 2. 注册表 schema

```yaml
version: 1
topics:
  - id: gold
    label: 黄金研判
    subtitle: ...
    asset: 黄金
    adapter: gold
    enabled: true
    order: 10
    refresh_job: collect_gold
    signal_weights: {fair_value: 12, trend: 14, volatility: 5, silver_ratio: 5,
                     inflation_expectation: 5, seasonality: 4}
    sections:
      - {id: conclusion, label: 结论与评分, kind: hero}
      - {id: kpis, label: 关键读数, kind: kpis}
      - {id: factors, label: 驱动因子, kind: factors}
      - {id: charts, label: 行情图表, kind: charts}
      - {id: valuation, label: 估值模型, kind: valuation}
      - {id: signals, label: 量化信号, kind: table}
      - {id: sources, label: 数据源与手动指标, kind: sources}
      - {id: health, label: 数据健康, kind: health}
      - {id: methodology, label: 方法论, kind: methodology}
```

`kind` 为闭集：`hero | kpis | factors | charts | bullets | table | valuation | scenarios | position | events | sources | health | methodology`。未知 kind 在配置校验时直接报错；payload 中未实现的分支会返回占位说明。

`config/topics/luoyang.yaml` 定义 `symbol/benchmarks/peers/assumptions/position_defaults/score_weights/datasets`。其中 `datasets[*].max_age_days` 供数据质检使用。

## 3. 统一响应契约

```ts
{
  meta: { topic_id, name, subtitle, asset, as_of, generated_at, config_version,
          adapter, refresh_job, status?, notes? },
  hero: { score, label, coverage, available_weight, total_weight,
          conclusion, badges, drivers, score_0_100 },
  sections: [{ id, label, kind, anchor, order, data }],
  verdict?: LuoyangVerdict          // 仅洛阳
}
```

前端类型见 `frontend/src/api/types/topic.ts`，各 kind 的归一化在 `utils/topicNormalize.ts`：

| kind | data 关键字段 |
|---|---|
| `hero` | 评分/标签/覆盖率/可用权重/结论/徽标/驱动 |
| `kpis` | `items[]`；黄金 `performance` 额外带 `regime/text` |
| `factors` | `groups[{key,label,contribution,available,items}]`、`factors[]`、`signals[]` |
| `charts` | `charts[]`（`kind: line/bar/candlestick/combo/scatter`、`dates/ohlc/series/bands/marks/hasData/emptyText`） |
| `table` | `{columns,rows,note}` 或 `{tables:[{id,title,columns,rows,note}]}` |
| `valuation` | 黄金：`fair_value/current_price/gap_pct/z_score/percentile/history`；洛阳：`pe_ttm/pb_mrq/ps_ttm/*_percentile/*_band_*/scorecards/peers/relative/series` |
| `scenarios` | `scenarios.{bear,base,bull}`、`weighted`、`methods`、`copper_grid`、`eps_source` |
| `position` | 成本/现价/浮盈亏/含分红回本/补仓表/持仓评分/触发条件/effective/defaults/overrides |
| `events` | `rows[{date,type,title,next_day,five_day,reaction}]`（前端兼容嵌套 reaction） |
| `sources` | `providers[]`、`manual[]`、`manualEditable` |
| `health` | `datasets[{name,rows,last,fresh,note}]`、`gaps`、`status` |
| `methodology` | `text/caveats/disclaimer` |
| `bullets` | `title/items` |

## 4. 存储与缓存

四张表（`backend/app/models/topics.py`，`init_db()` 自动建表）：

- `topic_datasets`：`(topic_id,dataset)` 唯一，目录/来源/频率/最新日期/行数；
- `topic_dataset_rows`：`(dataset_id,as_of,row_key)` 唯一，JSON payload，按 `as_of` 索引；
- `topic_source_runs`：每次 dataset 采集的成功/失败/记录数，90 天保留；
- `topic_settings`：持仓等页面覆盖值（JSON），不回写 YAML。

写入使用 SQLite `ON CONFLICT DO UPDATE`，同一批次内重复 `(as_of,row_key)` 先去重；`created_at` 在更新时刷新，使 overview 缓存键（`data_version`）随刷新推进。`/api/topics/{id}/overview` 有 25 秒进程内缓存，键包含 `config_version + data_version + series_limit`；持仓 PUT 与采集完成会清空缓存。

## 5. 洛阳钼业采集

`collect_luoyang`（每日 16:50，依赖 `collect_daily_bars`）逐 dataset 采集：行情/基准/商品汇率/估值/财务主要指标/三表/分部/两融/资金流/分红/公告/研报/同业快照。每个 dataset 独立 try/except，失败写 `topic_source_runs` 并继续；关键行情返回空或失败时回退系统 `market_bars`。详见 [05 数据源与接口清单](./05-数据源与接口清单.md) §2.3.1。

数据质检：`check_data_quality` 对 `price_daily/valuation_daily/financials_quarterly/benchmarks_daily` 按 `max_age_days` 检查，写 `DataCheck(action_job="collect_luoyang")`；系统状态页可一键补采。

## 6. 分析与评分口径

黄金：

- 17 项现有指标 + 6 项 golden 正交信号 + 复合动量，统一 `combine_factors`；
- 综合分 = `100 × Σ(w·s)/Σw`（仅可用权重），覆盖率 = 可用权重 / 总权重；
- 实际利率/美元/央行购金/ETF/COT 不重复计权；信号详情表保留 12 项展示口径并标注是否计权；
- 空数据时信号以 `available=false` 保留权重，避免覆盖率高估。

洛阳：

- 研判分 = 估值 30 + 技术 25 + 铜价 20 + 情景 15 + 相对强弱 10（`score_weights` 可改）；
- 估值：PE/PB/PS 分位、PB-ROE、股息、A/H、同业；技术：MA/RSI/MACD/BOLL/ATR/支撑阻力；
- 因子归因：单因子/多因子（Newey-West）、滚动 beta/相关、领先滞后、收益分解、两融与资金流；
- 情景：熊/基准/牛（铜价 × 四法 PE/PB/EV-EBITDA/DCF 加权）+ 铜价敏感性网格；
- 持仓：不复权成本、含分红回本、分批补仓测算、持仓评分与触发条件；持仓分不进入市场研判分；
- 缺数据逐块 `ok=false`/空态，不编造数字；`data.py::_assess` 给出 `ok/degraded/blocked` 与缺口说明。

## 7. 页面与交互

- 路由：`/topics/:topicId?`；`/gold` 重定向到 `/topics/gold`；侧栏「专题研判」、命令面板可直达两个专题。
- `TopicsView`：tab → 页头（数据截至/生成时间/刷新）→ 吸顶锚点导航 → 按 `section.order` 渲染 `TopicSectionBody`。
- 每个 section 以 `anchor` 作为 DOM id，`scroll-margin-top` 适配顶栏；锚点点击同步 URL hash。
- 图表：`TopicChartGrid` + `buildTopicChartOption`，支持 line/bar/candlestick/combo、分位带与成本/支撑线、时间范围（1 月–全部）。
- 持仓：`TopicPositionSection` 内置抽屉，PUT `/api/topics/luoyang/position`；覆盖值写入 `topic_settings`。前端只提交用户实际修改的字段。
- 黄金手动指标：`TopicSourcesSection` 抽屉调用现有 `POST /api/gold/metrics`。

## 8. 扩展步骤

1. 在 `config/topics.yaml` 增加 topic（id/label/adapter/sections/refresh_job）。
2. 需要独立参数时增加 `config/topics/<id>.yaml`。
3. 在 `backend/app/topics/__init__.py::ADAPTERS` 注册 `"<id>": "app.topics.<mod>:build_overview"`。
4. adapter 返回 `{meta,hero,sections,verdict?}`；section 的 `kind` 使用现有闭集，`data` 形状按 §3。
5. 采集任务：新增 collector + 在 `jobs/plan.py`/`runner.py`/`init_db.py` 注册；写入 `topic_datasets/topic_dataset_rows` 即可复用质检与页面。
6. 前端通常无需改代码；仅当新增 kind 时扩展 `TopicSectionKind`、`TopicSectionBody` 与渲染器。

## 10. 已知限制

- 东财接口在受限网络下可能不可达：采集器逐 dataset 降级，页面显示空态而不是报错。
- 黄金评分因并入信号与复合动量，历史分数会变化；旧 `/api/gold/overview` 键保持兼容但数值口径已更新。
- 洛阳情景使用配置兜底 EPS/净债务/D&A（研报或三表缺失时），文档与页面注明；三表已采集但当前主要作为展示/后续扩展。
- 持仓为个人数据，仅存本地 `data/epic.db`，不写入提交的配置文件。
