# 26 · 页面交互与信息架构

> 本文档是「页面该放什么、每个结论去哪下钻」的唯一约定。
> 新增页面前先读本文；改动页面职责时同步更新本文。

## 1. 导航分组（左侧菜单）

| 分组 | 页面 | 一句话职责 |
| --- | --- | --- |
| 今日 | 总览 `/` | 今天的结论与下一步动作：主线、KPI、关注、热力图、告警/日历摘要 |
| 今日 | 简报 `/briefs` | 早报 / 午报 / 收盘报 + 周报 / 月报（历史可回溯） |
| 今日 | 交易 `/trades` | 人工交易台账与复盘 |
| 市场 | 市场行情 `/market` | 全市场快照、会员持仓、品种分面 |
| 市场 | 利率与流动性 `/rates` | 利率曲线、流动性指标 |
| 专题 | 黄金研判 `/gold` | 黄金评分、因子明细、方法论（黄金唯一权威页） |
| 专题 | 交易信号 `/signals` | 信号清单与信号口径 |
| 预警 | 预警台 `/alerts` | 周期规则触发、阈值编辑、财经日历；主操作「逐条复核」 |
| 预警 | 预测台账 `/ledger` | 预测登记与结算；主操作「核对并结算」 |
| 证据 | 分析引擎 `/analysis` | 分析结论的**读**页面：风向、市场隐含周期象限、相关性、归因、相似交易日、日历事件后收益 |
| 证据 | 分析过程 `/pipeline` | 分析结论的**查**页面：运行序列、步骤链、方法注册表、推导清单、溯源 |
| 证据 | 分析依据 `/theses` | 论点、事件驱动、新闻政策、财经日历（日历唯一权威页） |
| 周期 | 周期罗盘 `/cycle` | 结构周期：五层、六分量、债务、世界秩序、历史类比 |
| 周期 | 世界长河 `/history` | 1500–2026 历史周期图谱 |
| 周期 | 原则库 `/principles` | 研判原则与核对 |
| 系统 | 系统状态 `/system` | 服务/数据库/调度/数据质量/验收；任务描述与执行历史 |

顺序约定：**先结论（今日）→ 再看市场 → 专题 → 预警（要处理的事）→ 证据（为什么）→ 周期（大背景）→ 系统**。

## 2. 唯一权威页与摘要页

同一份数据只允许有一个「权威页」完整展示，其余页面只放摘要 + 下钻链接。

| 数据 | 权威页 | 其它页面的呈现 |
| --- | --- | --- |
| 黄金评分与因子明细 | `/gold` | `/analysis` 只留分数、覆盖率、覆盖权重、前 4 驱动 + 「查看完整黄金研判」 |
| 运行序列与步骤链、方法注册表、推导清单 | `/pipeline` | `/analysis` 只留方法构成/代码指纹摘要、最近一次运行、E1–E4 分布 + 链接 |
| 数据质量明细 | `/system` 数据质检 | `/analysis` 只留通过率/未通过数/检查时间 + 链接 |
| 财经日历 | `/theses` 日历 | 总览留 6 行摘要；预警台只留与规则相关事件；市场日历用同一事件源 |
| 告警（Alert 表） | `/alerts` | 总览留 4 行摘要；顶栏铃铛进抽屉 |
| 周期结构研判 | `/cycle` | `/analysis` 的「市场隐含周期象限」只表示市场定价隐含象限，并在标题与副标题上与周期页区分 |
| 相似交易日 vs 历史类比 | `/cycle` 历史类比（20 维宏观） | `/analysis` 改名「相似交易日」（价格相似日 + 20 日远期收益） |
| 任务执行历史 | `/system` 任务调度 | 总览只显示调度器是否运行与下次运行时间 |

**总览 `/` 例外**：按要求保持聚合展示（主线、热力图、告警、日历等），它承担「一屏看今天 + 导航」，不作为任何数据的权威页。

## 3. 业务数据流（页面看到的数字从哪来）

```
采集 jobs（行情/新闻/利率/日历/持仓/研报）
  → 抽取 jobs（claims / events，含英文原文 + 中文对照）
  → 分析 jobs（analytics：风向、周期、相关性、归因、相似日、日历研究）
  → 决策 jobs（decision / theses：论点与动作）
  → 周期 jobs（cycle：五层读数、结构观测、情景）
  → 台账 jobs（ledger：登记与结算）
  → 预警 jobs（scan_alerts：阈值触发）
  → 简报 jobs（premarket 07:30 / postmarket 21:00 / weekly / monthly）
```

每个 job 的运行都会写 `job_runs`（状态、起止、摘要），玻璃盒页面（`/pipeline`）与「系统状态 → 调度次数」读同一份记录。

## 4. 交互惯例

1. **数字优先**：卡片先给结论数字，再给口径；口径放进 `card-foot` 或抽屉，不占主视线。
2. **摘要 + 下钻**：摘要卡片必须有明确出口（`→ 页面` / `为什么是这个读数 → 溯源` / 点击行打开抽屉）。
3. **弹框只做详情**：列表行点击打开 Drawer（历史走势、执行历史、证据明细），不在列表里塞长文本。
4. **空态要给出路**：空态文案写清「依赖哪个任务、去哪儿确认、重试按钮在哪」。
5. **表格**：
   - 默认禁止横向滚动条（`.table-wrap` 只允许纵向滚动，单元格允许换行）；
   - 代号、时间、数值、徽标用 nowrap；长文本列用 `cell-wrap`（最多两行）或 `cell-clip`（省略号 + `title`）；
   - 一张表建议 ≤ 8 列；同一语义的两列合并（如「类型 + 方向」）。
6. **中英对照**：事件、新闻、日历等英文文本统一用 `ZhText` 组件展示「中文（主）+ 英文（次）」，缺译时标注「暂无中文对照」。
7. **任务执行历史**：系统状态任务表最后一列显示调度次数，点击打开抽屉查看最近 200 次执行（开始时间/状态/耗时/摘要）。

## 5. 已知的页面职责边界

- `/analysis` 不再渲染方法注册表整表、运行列表、推导明细列表、数据质量整表；需要这些数据请去 `/pipeline` 与 `/system`。
- `/alerts` 的预警来自周期规则（`cycle.state.alerts`），与 Alert 表（`/api/alerts`，顶栏铃铛与总览告警）是两套对象；界面文案分别叫「周期规则预警」与「告警」。
- `/ledger` 只做登记与结算，不做预测生成；预测生成在 `/analysis` 与 `/cycle` 的结论里，登记时带上来源链接。
- 周报 / 月报与日报共用同一套表格样式与中英对照规则，不新增第二种排版。
