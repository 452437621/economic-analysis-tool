## 2026-11-14 · Windows 一键启动 / 停止 / 重启

### 新增

- `scripts/start.ps1` 重写：后台运行（WMI 脱离控制台 + 日志落盘）、就绪判定（healthz 200 且端口归属在进程树内）、PID 文件（启动器 + 真实服务双 PID）、自动开浏览器、`-Foreground/-Reload/-NoBrowser/-Port`。
- `scripts/stop.ps1`：按 PID 文件优先停真实服务，缺失时按端口兜底；校验命令行属于本项目，避免误杀；`-Force` 兜底；停止后清理 PID 并确认端口释放。
- `scripts/restart.ps1`：一键停止 + 启动。
- `scripts/_common.ps1`：端口探测（Get-NetTCPConnection → CIM → netstat 三层兜底）、进程树、健康检查（TcpClient，不依赖 System.Net.Http/代理）、PID 文件读写。
- `backend/app/serve.py`：后台启动器（重定向 stdout/stderr 到 `data/logs/server.*.log`，`-m app.serve` 方式避免 `app/platform` 遮蔽标准库）。

### 修复

- **`setup.ps1` 在 Windows PowerShell 5.1 下无法解析**：文件缺 UTF-8 BOM，中文被按 ANSI 解码导致引号错配；已为全部 `.ps1` 加 BOM。
- **一键启动"假成功/假失败"**：venv `python.exe` 是启动器，真实监听是其子进程；原逻辑比较单一 PID 导致误判。改为进程树判定并记录 `server_pid`。
- **启动脚本在捕获输出的终端中不返回**：`Start-Process` 让服务继承父进程 stdout 管道；改用 WMI 创建进程彻底脱离。

> V3.0 起：启停逻辑统一迁移到 `scripts/epic.py`（Windows 用 `DETACHED_PROCESS`，Linux 用 `start_new_session`），`_common.ps1` 已移除；本节保留为历史记录。
- **5.1 下健康检查恒失败**：`System.Net.Http` 默认未加载且 `Invoke-RestMethod` 走 IE 代理；改为 TcpClient 发最小 HTTP 请求。

### 遇到的问题与修复

| 问题 | 根因 | 处理 |
|---|---|---|
| 批量 UPSERT 报 `unable to open database file` (SQLITE_CANTOPEN) | 多行 UPSERT 触发 SQLite 临时文件；本机环境临时目录/文件句柄偶发不可用 | 连接级 `PRAGMA temp_store=MEMORY`；UPSERT 增加瞬时错误重试（幂等）；已验证稳定 |
| 沪深300 被写成 `192` | YAML 把未加引号的 `000300` 解析为整数 | 配置中给代码加引号，删除脏数据 |
| 玉米/豆粕等品种无数据 | 配置重写时漏掉农产品/黑色品种 | 补充 M/P/SR/CF/I 到配置，已回补 |
| 外盘/美债延迟与口径 | 免费源限制 | 界面徽标标注延迟；美债用官方 CSV；DXY 用代理算法并在名称标注 |
| 采集任务日志噪音大 | 异常打印完整 SQL | 后续统一日志级别与错误摘要（M1 收尾） |
