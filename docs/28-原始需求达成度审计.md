## 3. 逐项核对（关键细节）

### 3.1 「工具」的判据：读数必须是本地库的纯函数

`/lenses` 的所有读数都不联网、由 `app.cycle.market.load_panel()` 的日频面板 + `gold_metrics` 计算，因此同一输入必然复现同一输出。这是「工具」与「文章」的分界线：

- 面板：宏观 57 条序列 + 35 个标的日线（`macro_obs` / `market_bars`）；
- 读数：fed 21 条、song 31 条、宏观层 14 条、微观层 14 条、每位人物 14 条；
- 规则：36 条内置 + 9×8–12 条人物规则，逐条给出 `status`（fired/miss/unknown）、`trace`、`falsifier`。

### 3.2 「语义忠实」的判据：每条规则要能追到出处

- 美联储透镜的 F1–F12 对应笔记 R1–R15 的子集，取舍理由写在 `config/lens.yaml` 注释里；
- 宋鸿兵 S9（白银挤兑）因缺 COMEX 白银库存显示 `unknown`，**不填占位值**；
- 人物规则 `[sources]` 指向笔记与实际讲话条目；人物透镜整体带 caveat：「机械复刻框架，不代表本人当前观点」。

### 3.3 「预测与预警」的真实边界

| 能力 | 现状 | 差距 |
|---|---|---|
| 方向预测 | 7 资产 up/down/flat | 概率未校准（无 Brier 回测） |
| 情景 | 90 天 base/bull/bear + 触发/失效条件 | 情景概率未与历史频率对齐 |
| 结算 | 预测进 `forecasts`，到期按标的收盘价结算（长债用 US30Y） | 结算样本仍少 |
| 预警 | 规则命中 + severity + 并入预警台 | 无推送；无跨日去重（同一规则每日重复出现） |

## 4. 未达成 / 弱项清单（诚实版）

1. **仓位只到「建议」不到「执行」**：透镜给出止损、风险预算与组合权重（[`backend/app/lens/position.py`](../backend/app/lens/position.py)），但下单仍要人工在 `/trades` 确认；信号手数按标准权益 10 万计，实盘需按自有权益等比缩放。
2. **概率校准**：`probability` 是线性启发式，没有历史命中率反推，也没有 Brier 分数。
3. **预警通道**：只有页面与接口，没有邮件/IM 推送；规则每日重算，历史命中未做「首次触发」标记。
4. **数据缺口**（详见 [`docs/29`](29-数据源与数据完整性.md)）：COMEX 白银库存、IMF COFER、CIPS/人民币跨境、HY OAS、ACM 期限溢价、M2 长历史（H.6 只给当前页）。
5. **未工具化的框架**：宋鸿兵 S6（货币乘数/信用脉冲）与 S14（中国房地产长周期）因缺可计算序列未纳入；美联储的资产负债表工具（QE/QT 节奏）只有 H.4.1 原始序列，未做阶段判定。
6. **AI 解读**：`/api/v2/lenses/commentary` 需 LLM Key，当前默认不可用（返回 503 + 提示）。
7. **审核自动化**：13 套透镜的叙事文本为规则拼接，没有做「同一事件在不同人物框架下的对照叙述」。

## 6. 结论

原始需求的两条主线（美联储一脉、宋鸿兵）已经闭环：**读材料 → 提炼逻辑 → 做成工具 → 给出研判/预测/预警**，并且证据链可追溯、口径可复现、缺口显式披露。

第二轮第②项把「两人透镜」扩展为「13 套透镜 + 宏观/微观两层」，系统从「双镜对照」升级为「多维交叉验证」；第③项把结构性数据从 34 条扩到 **57 条**，并引入美联储资产负债表、M2、货币市场管道这三类此前完全没有的维度。

真正的短板集中在**决策落地与预测校准**，而不是分析框架本身。这两项已列入 P0。
